# 지난 대화를 찾아 웹에서 다시 열기

사용자는 대화 목록의 제목이 아니라 머릿속 기억("누구랑 무엇을 했던 것")으로 찾는다. 기억을 실마리 삼아 대화 기록을 직접 뒤진다.

## 1. 찾기

대화 기록은 `~/.claude/projects/*/<대화ID>.jsonl`이다(파일 이름이 대화 ID).

- 사용자 말에서 고유한 단어(사람 이름, 서버 이름, IP, 도구 이름)를 골라 검색한다. 한국어 이름은 성+이름, 이름만 둘 다 해 본다
  ```bash
  grep -l -i "조신혜" ~/.claude/projects/*/*.jsonl
  ```
- 후보가 여럿이면 단어를 더해 좁힌다(예: `조신혜`가 있는 파일 중 `ssh`도 있는 것)
- 후보마다 제목·마지막 수정 시각·폴더를 보여 줄 수 있게 모은다
  ```bash
  f=<파일>; grep -o '"aiTitle":"[^"]*"' "$f" | tail -1; grep -o '"customTitle":"[^"]*"' "$f" | tail -1
  stat -f '%Sm' "$f"; grep -m1 -o '"cwd":"[^"]*"' "$f"
  ```
- 맞는 대화가 하나로 분명하면 바로 연다. 둘 이상이면 제목·날짜·폴더를 짧게 보여 주고 사용자에게 고르게 한다

## 2. 열기

HQ 서버에 대화 ID를 넘기면 웹 안에 새 터미널로 그 대화가 이어 열리고, 사용자가 보고 있는 화면이 그 세션으로 넘어간다.

```bash
curl -s -H 'content-type: application/json' -H 'x-hq: 1' http://127.0.0.1:7420/api/session/resume -d '{"sid":"<대화ID>"}' | python3 -c "import json,sys;d=json.load(sys.stdin);print(d.get('error') or '열었습니다: '+d['result'])"
```

- 업무에 바로 묶고 싶으면 `"task":"<업무ID>"`를 함께 넘긴다. 업무 ID는 `curl -s http://127.0.0.1:7420/api/state`의 `tasks`에서 찾는다
- "다른 터미널에서 열려 있다"는 오류면 사용자에게 그곳에서 `/exit` 한 뒤 다시 하자고 알린다
- 이 대화(지금 이 세션) 자신을 열지 않는다

## 3. 알리기

어떤 대화를 왜 골랐는지(제목, 날짜, 근거가 된 단어) 한두 줄로 알린다.
